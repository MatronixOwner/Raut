# Raut

**Альтернатива Discord: скачал → зашёл → добавил друга → общаешься, созваниваешься и играешь.**

Пользователь просто устанавливает Raut (или открывает сайт), **регистрируется, добавляет друга по логину и сразу общается** — поднимать сервер, прописывать адреса и настраивать TURN ему не нужно. Аккаунты, токены сессий, список друзей, запросы, личные сообщения, присутствие, общие серверы и история хранятся на сервере проекта (пока общий сервер не развёрнут — на локальном сервере, который installer запускает сам). STUN/TURN и HTTPS задаёт администратор один раз при развёртывании.

Клиент внешне и по логике очень близок к Discord: рельса серверов, категории каналов, друзья и ЛС, чат, список участников, голосовая панель, индикаторы речи, шаринг экрана. Всё это работает и в полностью автономном режиме на локальном сервере — если общий сервер ещё не развёрнут.

В репозитории есть **готовый установщик для Windows** (`release/RautSetup-1.0.1.exe`), портативный ZIP и полный комплект для развёртывания центрального сервера: [deploy/README.md](deploy/README.md).

## Быстрый старт

### Windows (установщик)

**Как скачать — три способа:**

1. В открытом приложении Raut (live preview) на экране входа есть кнопка **«Скачать Raut для Windows»** — она отдаёт тот же `.exe` с заголовком `Content-Disposition: attachment`. Прямой адрес: `/download/RautSetup-1.0.1.exe` от корня вашего сервера.
2. Из репозитория: [release/RautSetup-1.0.1.exe](release/RautSetup-1.0.1.exe) → кнопка **Download / Скачать** в просмотрщике файла. Прямые ссылки на ветку:
   - `https://github.com/MatronixOwner/Raut/raw/arena/d55d4f5c-raut/release/RautSetup-1.0.1.exe`
   - `https://github.com/MatronixOwner/Raut/raw/arena/d55d4f5c-raut/release/Raut-1.0.1-portable.zip`
3. **Портативная версия без установщика:** [Raut-1.0.1-portable.zip](release/Raut-1.0.1-portable.zip) (или кнопка «Портативная версия» на экране входа / прямая ссылка `/download/Raut-1.0.1-portable.zip`). Распакуйте и запустите `Run-Raut.cmd` — никакого реестра, прав администратора и инсталлятора.
4. Собрать самостоятельно: `bash scripts/build-installer.sh` (см. ниже).

Контрольные суммы лежат рядом: `*.sha256`. Состав бинарников и их хэши — в `installer/BUILDINFO.txt` внутри установки.

**Установка:**

1. Запустите скачанный `RautSetup-1.0.1.exe`. Прав администратора не нужно — ставится в `%LOCALAPPDATA%\Raut`.
   SmartScreen может ругаться на отсутствие подписи: **Дополнительно → Выполнить**.
2. В меню «Пуск» появится `Raut`. Ярлык поднимет локальный сервер и откроет приложение в отдельном окне Microsoft Edge / Chrome без адресной строки. Если сборка сделана с `RAUT_PUBLIC_URL`, откроется сразу общий сервер.
3. **Зарегистрируйтесь** (логин + пароль) или войдите — токен сохранится, при следующем запуске вход будет автоматическим. Затем «Добавить друга» → логин друга → он принимает запрос → личный чат, голос и шаринг экрана. Можно также зайти как гость и общаться в общих каналах.

Требования: Windows 10/11 x64 + Microsoft Edge (есть в системе) либо Google Chrome.

### Linux / macOS / проверка без установки

```bash
node server/index.js --host 0.0.0.0 --port 8787
# открыть http://127.0.0.1:8787
```

Node.js 18+ (для HTTPS/WebSocket-клиента в тестах лучше 22+), внешних npm-зависимостей нет.

## Что внутри

| Компонент | Описание |
|---|---|
| `server/index.js` | HTTP(S)-сервер клиента, REST (`/api/config`, `/api/health`, загрузка файлов до 15 МБ), **регистрация/вход по токену, друзья, запросы, личные сообщения, presence**, сигналинг WebRTC, чат, каналы, серверы; всё состояние в `data/state.json` |
| `server/ws.js` | Своя реализация RFC 6455 на чистом Node.js (без `ws` и без `node_modules`) |
| `client/` | SPA: экран входа/регистрации, друзья и ЛС, чат, настройки, профили, уведомления |
| `client/config.js` | адрес центрального сервера (подставляется при сборке) |
| `deploy/` | Dockerfile, docker-compose (Raut + Caddy/TLS + coturn), systemd-юнит, Caddyfile, инструкция |
| `client/rtc.js` | Opus 48 кГц stereo, SDP-тюнинг, FEC, отдельные peer'ы для видео, VAD, статистика канала |
| `installer/raut.nsi` | NSIS 3: MUI2, русский/английский, компоненты, ярлыки, запись в «Программы и компоненты», uninstaller |
| `--open --no-console` в `server/index.js` | Открывает клиент в окне Edge/Chrome; ярлыки запускают `bin/nodew.exe` (GUI-подсистема PE). **Нет консоли, VBS/WSH и скрытых окон** |
| `scripts/` | Генератор иконки и сборка `.exe` |
| `release/` | `RautSetup-1.0.1.exe` (NSIS) + `Raut-1.0.1-portable.zip` + контрольные суммы `.sha256` |

### Качество связи

- **Звук:** WebRTC / Opus, 48 кГц, стерео, `maxaveragebitrate` 64–510 кбит/с (по умолчанию 256), `useinbandfec=1`, приоритет `high`, DTX выключен. Эхоподавление, шумоподавление и AGC настраиваются по отдельности (для музыки шумодав лучше выключить). Выбор микрофона и устройства вывода (`setSinkId`), громкость каждого собеседника, индикатор речи через DataChannel, статистика RTT/потерь/джиттера.
- **Экран:** `getDisplayMedia` до 3840×2160 / 60 FPS / 30 Мбит/с, системный звук, курсор, `maintain-resolution`. Видео идёт по **отдельным** RTCPeerConnection, поэтому включение трансляции не пересогласует звук и не обрывает голос. Несколько одновременных трансляций — плиткой.
- **Шифрование:** DTLS-SRTP, сквозное. Сервер видит текст чата и сигналинг, но не медиа.

## Сеть и работа в России

Российские провайдеры, двойной NAT и симметричный фаервол — основная причина, по которой P2P-звонки «не соединяются». Решение — свой **TURN**-сервер (coturn) и **HTTPS**.

### 1. Локальная сеть (квартира / офис)

Запустите ярлык **«Сервер Raut»** — он покажет адрес вида `http://192.168.1.42:8787/`. Другие открывают его в браузере или вводят на экране подключения Raut.

> Для LAN через обычный `http://IP` браузер считает страницу **небезопасным контекстом** и может запретить микрофон/экран. Используйте `127.0.0.1` на машине с сервером, либо поднимите HTTPS (см. ниже), либо запустите Chrome/Edge с флагом `--unsafely-treat-insecure-origin-as-secure=http://192.168.1.42:8787`.

### 2. Центральный сервер проекта (основной сценарий)

Готовый комплект — [deploy/README.md](deploy/README.md): один `docker compose up -d --build`
поднимает приложение, Caddy с автоматическим TLS и собственный coturn.
Пользователи заходят на `https://chat.example.ru`, регистрируются и общаются.
Администратор один раз задаёт домен, пароль TURN и делает бэкап `state.json`.

```bash
cd deploy
export DOMAIN=https://chat.example.ru DOMAIN_HOST=chat.example.ru TURN_PASSWORD='...'
docker compose up -d --build
```

Без Docker — прямое подключение TLS или systemd-юнит (`deploy/raut.service`):

```bash
RAUT_PUBLIC_URL=https://chat.example.ru \
node server/index.js --host 0.0.0.0 --port 443 \
  --cert /etc/letsencrypt/live/example.ru/fullchain.pem \
  --key  /etc/letsencrypt/live/example.ru/privkey.pem
```

Переменные окружения сервера:

| Переменная | Назначение |
|---|---|
| `RAUT_HOST`, `RAUT_PORT` | Адрес и порт (по умолчанию `0.0.0.0:8787`) |
| `RAUT_TLS_CERT`, `RAUT_TLS_KEY` | Пути к сертификату и ключу → включается HTTPS/WSS |
| `RAUT_TURN_URL` | `turn:turn.example.ru:3478` (можно несколько через запятую) |
| `RAUT_TURN_USER`, `RAUT_TURN_PASS` | Учётные данные TURN |
| `RAUT_STUN` | Список STUN через запятую. **По умолчанию пусто** — зарубежные STUN (Google и др.) не используются |
| `RAUT_PUBLIC_URL` | Публичный адрес центрального сервера; попадает в `/api/config`, `client/config.js` и ярлыки сборки |
| `RAUT_NAME`, `RAUT_DATA_DIR`, `RAUT_CLIENT_DIR` | Имя, папка данных, папка клиента |
| `RAUT_OPEN` / `--open` | Открыть окно приложения при запуске сервера |

Полный список и значения по умолчанию — в [deploy/README.md](deploy/README.md).

Пример `docker-compose.yml` для coturn:

```yaml
services:
  coturn:
    image: coturn/coturn:4.6.2
    network_mode: host
    command: >
      -n --log-file=stdout
      --listening-port=3478 --tls-listening-port=5349
      --fingerprint --lt-cred-mech
      --realm=turn.example.ru
      --server-name=turn.example.ru
      --user=raut:СЛОЖНЫЙ_ПАРОЛЬ
      --min-port=49152 --max-port=65535
      --no-multicast-peers --no-cli
```

Пользователю ничего прописывать не нужно: STUN/TURN задаются один раз на сервере и приходят в `/api/config`.

> Рекомендуется разместить VPS и TURN в РФ: тогда и сигналинг, и медиа при симметричном NAT остаются внутри страны, а задержка минимальна. **По умолчанию список ICE пуст** — никаких зарубежных сервисов; в одной локальной сети WebRTC соединяется напрямую, а для интернета администратор задаёт свой STUN/TURN на сервере. Пользователю настраивать ничего не нужно: клиент получает `iceServers` в `/api/config`.

## Сборка установщика `.exe`

```bash
bash scripts/build-installer.sh
# → release/RautSetup-1.0.1.exe
# → release/RautSetup-1.0.1.exe.sha256
# → release/Raut-1.0.1-portable.zip + .sha256

# Сборка, которая сразу открывает общий сервер:
RAUT_PUBLIC_URL=https://chat.example.ru bash scripts/build-installer.sh
```

`RAUT_PUBLIC_URL` записывается в `client/config.js`, добавляется как `--public-url`
в ярлыки NSIS и `Run-Raut.cmd`. Тогда установленная программа открывает общий
сервер, и пользователь только регистрируется — свой сервер ему поднимать не надо.

Скрипт работает на Linux **без Wine**: `makensis` из [electron-builder-binaries](https://github.com/electron-userland/electron-builder-binaries) собирает настоящий 32-битный PE-установщик для Windows, а `node.exe` (Windows x64) берётся из npm-пакета `node-win-x64`. Оба артефакта кешируются в `.cache/` и в Git не попадают. NSIS-установщик включает: сжатый LZMA-полный набор файлов, MUI2 с русским и английским языками, выбор компонентов, ярлыки, uninstaller и запись в реестре `HKCU\...\Uninstall\Raut`.

Дополнительно:

```bash
npm run icon       # пересобрать client/assets/logo.png и installer/Raut.ico
npm run check      # синтаксическая проверка всего JS
npm run dev        # локальный сервер для разработки
```

GitHub Actions (`.github/workflows/build-installer.yml`) собирает тот же `.exe` на `ubuntu-latest` и выкладывает артефакт.

## Архитектура соединения

```
Клиент A ──WebSocket──┐                    ┌──WebSocket── Клиент B
                      ├── Raut Server ─────┤
Клиент C ──WebSocket──┘  (аккаунты,       └──WebSocket── Клиент D
                          друзья, ЛС,
                          presence, чат,
                          сигналинг, файлы)
        └───────────── WebRTC (DTLS-SRTP) ─────────────┘
              Opus-аудио + отдельные видео-потоки
              + TURN-ретрансляция при симметричном NAT
```

- Одно `RTCPeerConnection` на собеседника для звука (ячеистая топология, отлично до ~8–10 человек) и одно на собеседника для экрана.
- Инициатор offer'а выбирается детерминированно (меньший `id`), поэтому glare-ситуаций нет; ICE-кандидаты буферизуются до `setRemoteDescription`.
- Для больших комнат (>10) рекомендуется заменить mesh на SFU (mediasoup/Janus) — сигналинг уже разделён с медиа и сделать это можно без переделки клиентского UI.

## «При скачивании пишет: обнаружен вирус»

Это **ложное срабатывание**, а не вирус. Причины ровно три, и все они типичны для любой небольшой open-source сборки:

1. **Нет Code Signing-сертификата.** Неподписанные `.exe` SmartScreen и Defender помечают как «неизвестный издатель», а часть эвристик — как потенциально вредоносные. Сертификат стоит денег и привязан к юрлицу; подписать сборку здесь невозможно.
2. **NSIS + LZMA + встроенный PE.** Установщик сжимает настоящий `node.exe` (87 МБ) внутри себя — упаковщик определяют как «пакер». Все легальные NSIS-инсталляторы выглядят так же.
3. ~~VBS-лаунчеры со скрытым окном~~ — **убраны в версии 1.0.0**. Раньше `Raut.vbs` делал `WScript.Shell.Run ..., 0, False` (скрытый запуск), и это самый частый триггер `Trojan:Script/...`. Теперь ярлыки указывают напрямую на `bin\nodew.exe --open --no-console` (без консольного окна), а окно браузера открывает сам сервер через `child_process.spawn`. Скрытых окон, WSH/VBS и автозапуска в сборке нет.

**Как убедиться самому:**

```powershell
# Windows PowerShell, в папке со скачанным файлом
Get-FileHash .\RautSetup-1.0.1.exe -Algorithm SHA256
# сверить с release/RautSetup-1.0.1.exe.sha256
Get-FileHash .\bin\node.exe -Algorithm SHA256
# сверить с BUILDINFO.txt внутри установки
```

- Проверьте файл на <https://www.virustotal.com/gui/home/upload> (если 1–2 малоизвестных движка ругаются при 70 чистых — это эвристика «пакер/неподписано»).
- Соберите из исходников: `git clone … && bash scripts/build-installer.sh` — состав бинарников и их хэши зафиксированы в `BUILDINFO.txt`.
- Defender уже заблокировал: **Безопасность Windows → Защита от вирусов и угроз → Журнал защиты → Разрешить на устройстве**.
- Не хотите связываться с инсталлятором: скачайте **портативный ZIP** и запустите `Run-Raut.cmd`.

Если срабатывает конкретный антивирус с конкретным именем угрозы (например `Trojan:Win32/Wacatac` или `HEUR:Trojan.Script.Generic`) — напишите мне точный текст: по названию детекта можно точечно убрать ещё один паттерн. Для радикального решения нужен только EV/OV-сертификат и `signtool sign /fd SHA256`.

## Ограничения и честные замечания

- Это **работающий MVP**, а не буквальный клон Discord: нет ролей/прав, горизонтального масштабирования, мобильного приложения, push-уведомлений и скриптов ботов. Аккаунты, друзья, ЛС и история живут в JSON одного процесса (`state.json`). Пароли хэшируются `scrypt`, но пока нет rate-limit на вход, восстановления пароля и E2EE чата.
- Для настоящего публичного сервиса нужны VPS, домен, TLS и свой TURN — готовый комплект в [`deploy/`](deploy/README.md), но сами ресурсы предоставляет владелец проекта.
- Для созвонов больше ~10 человек mesh нагружает исходящий канал — нужен SFU.
- Установщик **не подписан** (нет сертификата Code Signing), поэтому Windows SmartScreen покажет предупреждение. Для распространения купите EV/OV-сертификат и подпишите `signtool sign /fd SHA256 …`.
- WebRTC-медиа не расшифровывается сервером, но текст чата хранится в открытом виде в `data/state.json` — шифруйте диск при необходимости.
- Всё это полностью легально и автономно: приложение не обходит блокировки, а просто не использует заблокированные сервисы.
