# Свои сервера Raut — что уже готово и что нужно от вас

## Коротко

Код для централизованной работы **готов**: аккаунты, вход по токену, друзья по логину,
запросы в друзья, личные сообщения, presence и общие серверы/каналы хранятся на сервере.
Пользователь устанавливает программу (или просто открывает сайт), регистрируется, добавляет
друга по логину и сразу общается — **никакой настройки сервера на его компьютере не требуется**.

Но чтобы это стало «нашим сервером», а не локальным превью, нужен **реально существующий
VPS и домен**. В этом репозитории нет ни арендованной машины, ни домена, ни ключей к ним —
их может предоставить только владелец проекта. Ниже готовый комплект развёртывания:
выполните шаги на своём VPS, и installer/сайт будут работать у всех пользователей.

> ВАЖНО про HTTPS. `getUserMedia` (микрофон) и `getDisplayMedia` (показ экрана) браузер
> разрешает только в **защищённом контексте**: `https://...` или `localhost`.
> Поэтому общий сервер обязан быть за TLS-прокси (Caddy/nginx). По голому `http://IP`
> чат будет работать, а микрофон и демонстрация экрана — нет.

## Что вам понадобится

| Что | Зачем | Ориентир |
| --- | --- | --- |
| VPS в РФ (или с доступом из РФ) | сам сервер Raut + TURN | 2 vCPU, 2–4 ГБ RAM, Ubuntu 22.04/24.04 |
| Домен, A/AAAA-запись на VPS | HTTPS истабильный адрес | `chat.example.ru` |
| Открытые порты | 80, 443 (TCP + UDP), 3478 TCP/UDP, 5349 TCP | 80/443 для Caddy, 3478 для TURN |
| Docker + docker compose | запуск комплекта | `curl -fsSL https://get.docker.com \| sh` |

Домен и VPS лучше брать у российского провайдера, чтобы не зависеть от зарубежных
сервисов: это прямо влияет на требование «работать в России».

## Вариант 0 — одна команда (рекомендуемый)

```bash
sudo bash one-shot.sh chat.example.ru
```

Всё, что описано ниже (Docker, TLS-сертификат, Caddyfile, coturn, пароль TURN,
`RAUT_PUBLIC_URL`, демо-пользователи), скрипт делает сам. На выходе — готовая ссылка
`https://chat.example.ru` для вас и друга. Впишите её в `SERVER_URL.txt` в корне репозитория,
и **все уже установленные копии Raut перейдут на неё без переустановки**.

## Вариант A — Docker (рекомендуемый, 5 минут)

```bash
git clone https://github.com/MatronixOwner/Raut.git
cd Raut/deploy

# 1. Укажите свой домен в Caddyfile (замените chat.example.ru и admin@example.ru)
nano Caddyfile

# 2. Придумайте пароль TURN и вставьте его в два места:
#    turnserver.conf → user=raut:ВАШ_ПАРОЛЬ
#    переменная TURN_PASSWORD при запуске
nano turnserver.conf

# 3. Запуск
export DOMAIN=https://chat.example.ru
export DOMAIN_HOST=chat.example.ru
export TURN_PASSWORD='ВАШ_ПАРОЛЬ'
docker compose up -d --build

# 4. Проверка
curl https://chat.example.ru/api/health
docker compose logs -f raut
```

Состав:

| Сервис | Роль |
| --- | --- |
| `raut` | Node.js-сервер: аккаунты, друзья, ЛС, чат, presence, WebRTC-сигналинг, раздача клиента и installer |
| `caddy` | автоматический TLS (Let's Encrypt) + reverse proxy с поддержкой WebSocket (`wss://`) |
| `coturn` | собственный STUN/TURN, чтобы голос и экран работали за NAT и симметричным файрволом |

Данные (аккаунты, токены, друзья, история, загрузки) лежат в docker-volume `raut-data`
в `/data/state.json`. **Делайте бэкап** этой папки:

```bash
docker run --rm -v deploy_raut-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/raut-backup-$(date +%F).tgz -C /data .
```

Обновление: `git pull && docker compose up -d --build`.

### Если Let's Encrypt недоступен

Caddy можно заменить на nginx с сертификатом от российского удостоверяющего центра,
либо выдать свой сертификат и запустить Raut напрямую:

```bash
RAUT_TLS_CERT=/etc/ssl/raut.crt RAUT_TLS_KEY=/etc/ssl/raut.key \
RAUT_PUBLIC_URL=https://chat.example.ru \
node server/index.js --host 0.0.0.0 --port 443
```

## Вариант B — systemd без Docker

```bash
sudo useradd -r -m -d /opt/raut raut
sudo mkdir -p /opt/raut /var/lib/raut
sudo cp -r server client package.json /opt/raut/
sudo cp deploy/raut.service /etc/systemd/system/raut.service
sudo nano /etc/systemd/system/raut.service   # домен, пароль TURN, пути
sudo systemctl daemon-reload && sudo systemctl enable --now raut
```

Дальше — TLS-терминация на nginx/Caddy и отдельный coturn по `turnserver.conf`.
Юнит уже содержит все переменные окружения (см. файл).

## Переменные окружения сервера

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `RAUT_HOST` / `RAUT_PORT` | адрес и порт | `0.0.0.0` / `8787` |
| `RAUT_DATA_DIR` | аккаунты, токены, история, загрузки | `./data` |
| `RAUT_CLIENT_DIR` | папка веб-клиента | `./client` |
| `RAUT_PUBLIC_URL` | публичный адрес; installer/клиент открывают его | пусто = локальный сервер |
| `RAUT_TLS_CERT` / `RAUT_TLS_KEY` | прямой HTTPS без прокси | пусто |
| `RAUT_STUN` | свои STUN через запятую | **пусто** (никаких Google STUN) |
| `RAUT_TURN_URL` | свои TURN URL через запятую | пусто |
| `RAUT_TURN_USER` / `RAUT_TURN_PASS` | логин/пароль TURN | пусто |
| `RAUT_NAME` | имя сервера в интерфейсе | `Raut Server` |
| `RAUT_OPEN` / `--open` | открыть окно приложения при старте | выкл |

Клиент получает `iceServers` через `GET /api/config` и `welcome`. Администратор задаёт
STUN/TURN один раз на сервере — пользователям ничего настраивать не нужно. Это и есть
ответ на «чтобы пользователям не надо было ничего делать».

## Собрать installer, который сразу идёт на общий сервер

```bash
RAUT_PUBLIC_URL=https://chat.example.ru bash scripts/build-installer.sh
```

Скрипт запишет адрес в `client/config.js`, добавит `--public-url` в ярлыки NSIS и
в `Run-Raut.cmd` портативной версии. После установки программа откроет
`https://chat.example.ru` в отдельном окне Edge/Chrome, и пользователь увидит экран
входа/регистрации. Локальный `node.exe` при этом всё равно поднимает копию сервера —
это безвредный офлайн-фолбэк; при желании его можно убрать, оставив только ярлык на сайт.

Если `RAUT_PUBLIC_URL` не задан, сборка остаётся полностью автономной (как раньше):
все пользователи подключаются к одному локальному серверу вручную.

В GitHub Actions тот же адрес задаётся **переменной репозитория**
`Settings → Secrets and variables → Actions → Variables → RAUT_PUBLIC_URL`.
Workflow `build-installer.yml` передаёт её в сборку, поэтому артефакт из CI
сразу открывает общий сервер.

## Масштаб и ограничения (честно)

- **Голос/экран — mesh (peer-to-peer)**: каждый участник отправляет поток каждому.
  Отлично для 2–8 человек; далее нужен SFU (mediasoup/Janus/LiveKit) на том же VPS.
  Сигналинг и чат уже централизованы и выдержат сотни соединений.
- **Хранилище — JSON-файл** (`state.json`), запись с дебаунсом 400 мс. Для сотен
  пользователей хватит; для тысяч нужна PostgreSQL/SQLite + отдельные таблицы.
- **Пароли** хэшируются `scrypt` с уникальной солью; сессии — случайные 256-битные
  токены, в базе хранится только SHA-256 токена. Пароли в открытом виде не пишутся.
  Нет rate-limit на логин и нет восстановления пароля — добавьте перед публикацией.
- Нет шифрования «end-to-end»: сервер видит текст сообщений. Для приватности нужен
  отдельный E2EE-слой.
- **Нет code signing** у installer → возможны предупреждения SmartScreen/антивирусов.
- TURN в Docker использует `network_mode: host`; на VPS с Docker Desktop это работает
  иначе — проверьте порты 3478/5349.
- Юридически: для публичного сервиса в РФ понадобятся политика обработки ПДн,
  уведомление Роскомнадзора и, при определённом масштабе, регистрация в реестре ОРИ.

## Что нужно решить владельцу проекта

1. **VPS**: какой провайдер, регион, конфигурация, кто имеет доступ.
2. **Домен**: какое имя, у кого регистратор, готовы ли DNS-записи.
3. **Режим входа**: только логин+пароль (сейчас) или нужен вход по e-mail/телефону и
   восстановление пароля.
4. **Нужен ли SFU** (группы по 20+ человек в голосе) или пока хватит mesh.
5. **«Играете»**: это просто «играть вместе, общаясь в голосе» (уже работает) или
   нужны игровые статусы/приглашения в игру/Rich Presence (пока нет — скажите, добавим).
6. **Code signing**: покупать сертификат или оставить portable ZIP как основной вариант.

Дайте домен и доступ к VPS — и я разверну это, проверю HTTPS/WSS/TURN и соберу installer
с уже прописанным адресом. Пока их нет, локальный предпросмотр и `docker compose`
полностью воспроизводят ту же архитектуру.
